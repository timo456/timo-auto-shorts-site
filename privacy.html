Privacy Policy

Effective and last updated: October 25, 2026

Timo Auto Shorts processes media on your Windows computer and connects to YouTube only with your authorization.

1. Scope and operator

This policy covers the Timo Auto Shorts desktop application and this informational website. The project is maintained by Timo (GitHub account timo456), reachable at timo456.op@gmail.com. The current application is a local, personal channel-management tool; it has no central account system or hosted media-processing backend.

2. Data the application accesses

  • Local media: video and audio files in folders you choose, filenames and paths, file sizes, modification times, durations, technical media properties, and content hashes used to identify files and avoid repeat selections. Processing creates separate video exports and caption files; it does not alter the source training videos.
  • Music information: imported audio copies, track titles, sources, license conditions, attribution text, and your confirmation that you may use the music.
  • Google authorization: OAuth access and refresh tokens, granted scopes, expiration information, and desktop OAuth client configuration. Google handles sign-in; the app does not collect your Google password.
  • YouTube account and video information: the authorized channel’s ID, name and handle; video IDs, URLs, titles, descriptions, and the metadata, privacy, scheduling, upload and processing information returned for videos managed or explicitly linked in the app. The app saves the returned video resource, not only the status displayed in its interface.
  • Local workflow records: Day numbers, selected source files, generated text, music selections, settings, publishing times, resumable-upload session URLs and progress, status-check times, and operational or error records.

3. Google API permissions

The current implementation requests these three scopes through Google OAuth 2.0 and uses YouTube Data API v3:

Requested scopes and current use
ScopePurpose in this app
https://www.googleapis.com/auth/youtube.uploadUpload prepared videos and their titles, descriptions and other upload metadata.
https://www.googleapis.com/auth/youtube.readonlyCheck channel identity and retrieve video metadata and remote status.
https://www.googleapis.com/auth/youtube.force-sslUpdate video status to set an authorized publishing schedule. This permission is broader than the app’s current use: it also permits changes to, and deletion of, YouTube videos, ratings, comments and captions. The current code does not read or manage ratings, comments or captions, and does not delete YouTube videos.

The app does not request Gmail, Drive, contacts, or YouTube Analytics permissions. Google shows the permissions during authorization; you can decline access or revoke it later.

4. Local storage and security

Credentials are saved as JSON files in the application’s local secrets folder so the desktop app can refresh authorization without repeated sign-in. On Windows, the app restricts that folder’s NTFS access permissions to the current user and SYSTEM. These files are not encrypted by the application.

Settings are stored in a local JSON file. A local SQLite database stores media indexes, draft and music records, upload sessions, and returned YouTube metadata. Exports and caption files are stored in the local output folder. Worker logs are local and rotate by file size; other records and any backups remain on local storage. The app does not provide database or media encryption.

Google OAuth and API requests use HTTPS; the desktop authorization flow also uses a temporary local loopback callback. Protect your computer, backups and file permissions. Do not share credentials, upload-session URLs, databases or unreviewed diagnostic files. Local access controls cannot protect data from every compromised computer or privileged account.

5. How data is used and shared

Data is used to prepare videos, choose and credit music, generate numbered captions, confirm the intended channel, resume uploads, prevent duplicate work, and check or set publishing status.

When you authorize an upload, the rendered video, title, description, tags, category, audience setting and relevant status or scheduling instructions are sent directly to Google/YouTube. Music credits included in a description are sent with it. Google also receives authentication and technical request information. The original media library and database are not uploaded as a collection.

New API uploads start private. Public scheduling requires enabling Auto Publish and leaving test mode. Published video content and descriptions become available according to their YouTube visibility. YouTube’s handling of data is governed by Google’s Privacy Policy and the YouTube Terms of Service.

The application has no advertising or analytics integration and does not send Google user data to the maintainer’s server. It does not sell Google user data, use it for advertising, or use it to train AI models. Timo Auto Shorts’ use and transfer of information received from Google APIs is limited to the user-facing functions described here and is subject to the Google API Services User Data Policy, including its Limited Use requirements.

If you contact the maintainer, the information you voluntarily include is used to respond. Please do not send tokens, client secrets, private videos or database copies. The maintainer cannot remotely inspect or erase files on your computer.

6. Retention, revocation and deletion

The current version does not automatically expire its local database records, stored API responses, exports or backups. They remain until you remove them. Remote status is refreshed when a status-check or upload/scheduling operation runs; there is no automatic, time-based purge of old API data or deletion following revoked authorization. This describes the current implementation, not a claim that it has passed Google’s data-retention review.

To stop access, revoke Timo Auto Shorts in your Google account security settings. Then stop the desktop app and any Windows scheduled task that runs it. Revocation prevents future authorized access but does not itself erase existing local files or YouTube uploads.

To remove local data, first stop the app and worker. Remove the saved OAuth token to remove local authorization. For a complete local reset, also remove the application’s settings, local database and associated files, generated exports, imported music copies, logs, and any backups containing those records. This erases local publishing history and deduplication information; do not restart an old queue without reviewing it. You can contact the maintainer for help identifying these files without sending their contents.

Manage or delete uploaded videos and cancel existing publication schedules separately in YouTube Studio. Deleting local files or turning off Auto Publish does not cancel schedules already accepted by YouTube. Google’s own retention practices apply to data it receives.

7. Website visitors

This website consists of public static pages hosted by GitHub Pages. It contains no sign-in form, upload form, embedded video, analytics script, or application-set tracking cookies. It does not receive the desktop app’s Google credentials, database or media.

GitHub may process visitor IP addresses and request information to operate and secure its hosting service, under the GitHub General Privacy Statement. Following an external link or sending email uses the destination provider’s services and policies.

8. Questions and changes

For privacy questions, complaints or help removing local data, contact timo456.op@gmail.com. This page will be updated when the application’s data practices change, with a revised date at the top.
